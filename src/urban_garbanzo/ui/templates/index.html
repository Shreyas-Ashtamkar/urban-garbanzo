Prompt evaluation

Know where a prompt will fail before the model tells you the expensive way.

urban-garbanzo helps teams review prompts as working instructions, not just text blobs. You can inspect whether the ask is clear, bounded, specific, dense enough to be useful, and safe enough to avoid inviting low-trust output.

Instead of bouncing between vague rewrites and repeated model runs, the editor gives you a tighter loop: draft, score, understand the rationale, and improve the prompt with a more obvious next step.

Support escalation reply 84 / 100

"Write a customer support reply for a delayed enterprise contract renewal. Keep it empathetic, state the blocker, and give a concrete next update time."

Clarity 91 Correctness 82 Density 79 Risk 18

This prompt already does two important things right: it names the context and it asks for a practical response shape. The score stays below the top band because the model still has to guess escalation boundaries, message length, and how much commercial detail should be disclosed.

Fintech launch checklist 92 / 100

"Generate a launch checklist for a new fintech onboarding flow. Group tasks by legal, analytics, design QA, and rollback readiness."

Clarity 94 Correctness 90 Density 93 Risk 10

The categories give the model a strong organizing frame, which sharply reduces drift. What would make it even better is asking for owners, exit criteria, and explicit launch blockers so the output becomes directly operational.

Roadmap summary rewrite 73 / 100

"Summarize this roadmap and make it better."

Clarity 58 Correctness 81 Density 54 Risk 27

The request signals intent but not standards. The model has to invent what “better” means, for whom the summary is written, how much to preserve, and what structure the final answer should follow.

Workflow

A clearer prompt-review loop, shown as a sequence instead of a pile of features.

The point is not to collect scores for their own sake. The point is to move from rough prompt to reliable prompt with an obvious path between each step.

01

Draft the instruction with intent

Start with the real task, target audience, expected output shape, and any hard constraints. This makes the first evaluation meaningful instead of cosmetic.

02

Inspect how the prompt is likely to behave

Read the scoring dimensions as a map of weaknesses. Low clarity, low density, and elevated risk usually point to a specific revision problem, not a generic “bad prompt.”

03

Use the rationale to tighten the next version

Add boundaries, force output structure, reduce repetition, and make success criteria more explicit until the prompt stops leaving critical decisions to model guesswork.
